# Paperclip - Autonomous Computer AI Assistant

## Overview

Paperclip is an advanced **Autonomous Computer AI Assistant** built with a **fully modular capability-based architecture**. Every capability is implemented as an independent source code package with dedicated classes, utilities, configuration files, prompts, tests, and execution logic.

## AI Models

Paperclip uses only Google Gemini models:
- **Gemini 2.5 Flash** - Primary reasoning engine for complex tasks
- **Gemini 1.5 Flash** - High-speed processing for fast operations

## Project Structure

```
paperclip/
├── main.py                      # Entry point
├── config.yaml                  # Configuration
├── src/
│   ├── autonomous_execution_engine/  # Core coordinator
│   ├── model_router/            # AI task routing
│   ├── gemini_25_flash/         # Reasoning engine
│   ├── gemini_15_flash/         # Processing engine
│   └── <capability_name>/       # 113 independent modules
```

## Key Capabilities

- **Computer Automation**: Mouse, keyboard, screenshots, OCR, window management
- **OS Automation**: App launching, process management, system settings
- **File Management**: Search, copy, move, organize files
- **Browser Automation**: Web browsing, form filling, content extraction
- **Development**: Terminal, Git, Python execution
- **System Monitoring**: CPU, memory, disk, battery tracking
- **Power Management**: Shutdown, restart, sleep, lock

## Usage

```bash
cd paperclip
pip install -r requirements.txt
export GEMINI_API_KEY="your-api-key"
python main.py --task "your task here"
```

## Architecture

Each capability module is completely independent:
- Has its own `__init__.py`, `main.py`, `utils.py`, `config.yaml`, `prompts.md`, `tests.py`, `README.md`
- Can be enabled/disabled independently
- No shared code between capabilities
- Located in `src/<capability_name>/`

## New top-level structure (built at repo root)

A second, larger capability-based architecture lives at the repo root
(`/workspace/project/candy/`) alongside the `paperclip/` package. It was
generated by `build_structure.py` (mirrors `paperclip/generate_modules.py`
convention) and is fully importable + runnable.

Top-level files:
- `main.py` (entry point; starts daemons + UI)
- `ui.py` (text UI)
- `setup.py` (install deps + runtime dirs/secrets)
- `orchestrator.py` (LLM planner; breaks tasks into steps)
- `smart_orchestrator.py` (central brain; routes to everything)

Packages (each `__init__.py` auto-registers its modules at runtime):
- `actions/` (~245 tools) `automation/` (27) `smart_agents/` (20) `sensors/` (12)
- `autonomy/` (12) `security/` (12) `integrations/` (15) `ai_models/` (10)
- `memory/` (8 stores) `core/prompt.txt` `config/api_keys.json`

Every module exposes the standard `execute(task, context)` contract. Module
files use a shared template; `.format()`-based templates keep braces escaped as
`{{`/`}}`, while the plain-string top-level templates (orchestrator, smart
orchestrator) use single braces.

Run: `python3 main.py --task "..." --no-daemons` (works without API keys;
capabilities return stubs until implemented).

## Running Paperclip

```bash
# Interactive mode
python main.py

# Single task mode
python main.py --task "Open browser and search for news"

# With custom config
python main.py --config custom.yaml
```
